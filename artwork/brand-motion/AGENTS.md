# 蓝雪女仆品牌动效：已确认的经验与约定

这些约定来自用户在本任务中的明确反馈。未来新增和修改品牌动效时继续遵守。

## 先定义语义，再画图

- 每个状态先列出表情、两只手的位置、道具、动作起点和终点；三者都应能说明当前状态。
- 招手仅用于启动欢迎。禁止把同一张招手图加上不同道具当作其他状态。
- 不同状态不能全部使用开眼微笑。必须让眉眼、嘴形、头部方向或重心产生可辨认的区别。
- 保留白蓝长发、蓝眼睛、蕾丝女仆头饰、蓝色蝴蝶结和白蓝服装的角色身份。不要回退到用户否定的几何简笔画。
- 关注/取关不要用加减号、关注卡片等字面符号解释动作。用户要求关注角色更开心，并以项目 `blue-snow-maid-download-reference.png` 的精细半身女仆为身份与风格参考，不用之前的全身大头 Q 版；关注原画为 `blue-snow-maid-follow-happy-reference.png`。取关保持同一身份，但必须根据结束关注的场景独立设计表情与姿态，不能套用关注的开心笑脸。

## 分层与运行时踩过的坑

- 道具必须实际握在手里；手、腕、柄、镜片和眼睛需要逐帧检查。不能让镜片与眼睛在运动后错位。
- 每张新姿势都要重新测量眼睛、发梢和道具蒙版，不能复用欢迎姿势的坐标。
- 镜片覆盖眼睛时避免眼睛重复绘制；闭眼表情不能再把眼睛压扁当作眨眼。
- 蒙版减去的区域在道具移动后不能露出透明洞或多余轮廓；用合理底层补足并在深浅背景检查。
- 静态回退必须匹配该状态的独立姿势，不能加载失败后又显示欢迎招手图。
- RETRY 动作时长为 1.5 秒，单次播放后保留担心姿势；眨眼、插头微动及断线提示均在资源时间轴内结束。主体失败场景的重试使用主按钮，操作不等待动画完成；分页失败保留轻量重试入口。
- 接入时逐项检查加载失败、无结果和分页失败分支。搜索失败用断线角色，搜索无结果用放大镜角色；不能只接无结果而漏掉失败。
- 原画使用内置 imagegen；分层、关键帧及矢量效果在本地制作。不得把静态图片冒充已完成的动画。
- 默认单次播放。页面不可见或后台时暂停，恢复不把已完成动画重新播放；重播应是明确用户操作。
- 清理中是进行时循环的例外，仅在真实清理任务进行且可见时循环；后台暂停后接着播，减少动态或资源失败保持清理中静态姿势，不触发成功回调。成功、失败都由清理任务结果决定，不能等动画结束才处理。
- 成功角色优先放在内容区安全角落，避开画面中心、底栏、键盘和播放器控制区；横屏/短窗口缩小，清理弹窗要限高并可滚动。失败和空状态在扣除顶部与底部界面后的内容区居中。
- 区分动作时长和完成姿态停留：点赞停留 500ms、三连 600ms、收藏/下载 800ms。停留期间暂停恢复不能从头重播。三连跳转由对应庆祝完成触发，旧完成回调不能结束新的庆祝；未挂载/超时取消跳转。
- 成功反馈只来自真实成功事件。取消、失败、历史状态恢复不能误触发成功动画。不要给三连重复叠加收藏成功动画。
- 关注/取关只在接口确认成功后发出对应事件，乐观更新、取消确认、失败及拉黑/解除拉黑不发出。批量取关禁用逐个角色反馈，结束时只汇总实际成功项；全部失败不展示完成角色，部分失败保留失败数量。
- 检查资源引用、关键帧终点、离线加载、深浅背景和动作中间帧；报告应用内尚未验证的范围。

- 用户已取消下拉刷新女仆动画：保持原生 MD3/Miuix 刷新指示器，不重新接入刷新角色伴随反馈，除非用户再次明确要求。
- 点赞位置已更新为点赞图标右上方锚点：点踩、分享、投币共用 `LikeBurstAnchorRegistry.likeIcon.bounds` 的现有坐标计算，最大 144dp；只有锚点不存在时才使用原有右下角回退。不得按旧文档把默认位置改回右下角。单项反馈互相替换；旧事件回调不能关闭新反馈，包括更换视频以后。
- 收藏等全局反馈每次事件固定首次锚点；缺失时本次一直用回退位置，不因收藏面板关闭或后续按钮布局上报而跳到上方。卡片尺寸在同一次测量与放置中使用，不通过 `onSizeChanged` 回写后再纠正位置，避免首帧漂移。
- 应用 Lottie JSON 不再内嵌 Base64 PNG：`maid_bitmap.p` 引用对应 `drawable-nodpi` 静态回退文件名，运行时在播放前提供同一图片。保持原图尺寸和蒙版坐标；图片加载失败仍走该状态的静态回退。制作预览由 `package_assets.py` 单独内嵌图片，仅保存在 artwork，不进入应用资源；生成或转换后运行 `validate.py` 检查所有枚举与图片路径匹配，避免再次打包两份图片。
- 视频操作反馈的减少动态效果只跟随系统动画设置；不得关联默认关闭的“卡片进场动画”开关，否则点赞、三连等默认都只显示静态帧。
